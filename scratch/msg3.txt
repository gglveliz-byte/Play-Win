fix(sdk): el token nuevo del Hub nunca se usaba si ya habia un socket abierto

Sintoma: pantalla "ACCESO REQUERIDO - Token de partida no valido o expirado"
teniendo sesion iniciada, y despues la partida no arrancaba.

## Causa raiz

El SDK lee una sesion de localStorage al arrancar. El MatchTicket dura 5 MINUTOS,
asi que una sesion guardada de una visita anterior lleva un token caducado. El SDK
conecta con el, y el servidor lo rechaza con SECURITY_ERROR.

Acto seguido el Hub entrega un token NUEVO Y VALIDO por postMessage, pero:

  if (p.token) {
    if (!isSocketOpen()) connectWebSocket();   // si YA hay socket, NO reconecta
  }

El socket del token caducado seguia abierto, asi que la condicion era falsa y NO
se reconectaba: el jugador se quedaba en la pantalla de acceso con un token bueno
en la mano, sin usarlo nunca.

## Segundo defecto, en el mismo camino

El `retry` del gestor de conexion salia sin hacer nada cuando ya habia un socket
abierto, que es justo el caso en que hay que reconectar:

  retry: function () {
    if (socket && (... OPEN || ... CONNECTING)) return;   // no hace nada
    ...
  }

## Arreglos

1. Un token nuevo SIEMPRE fuerza la reconexion: se descarta el socket anterior y
   se abre uno nuevo con el token recien recibido. Reconectar es lo correcto
   porque la sesion vieja ya no sirve para nada.
2. Nuevo `descartarSocket()` en el gestor de conexion: anula los manejadores ANTES
   de cerrar (si no, el cierre dispararia la logica de reconexion y abriria un
   socket que no queremos) y cancela el reloj de conexion.
3. `retry()` pasa a descartar y reconectar SIEMPRE.
4. `retryConnection()` crea el gestor si todavia no existe, para que la primera
   entrega de token tambien funcione por esta via.

## test:retoken (nuevo)

Ejecuta los cuatro modulos reales del SDK con un WebSocket falso y una sesion
CADUCADA en localStorage, y reproduce la secuencia completa:

  - el SDK abre un socket con el token caducado         OK
  - el servidor lo rechaza con SECURITY_ERROR           OK
  - el Hub entrega un token nuevo                       -> se abre un socket NUEVO
  - el socket viejo queda DESCARTADO                    OK
  - el socket nuevo lleva el token BUENO                OK
